# DICKY / ONTIME

個人班表、出勤、通勤、用餐、睡眠及時間預算工具。

[開啟網頁](https://hasonk200.github.io/codex/)

## Firebase Sync
- 使用 Google 帳戶登入後，個人資料會透過 Firestore 同步到同一帳戶的其他裝置。
- Firestore 安全規則限定登入者只能讀寫自己 UID 下的資料；雲端紀錄採用不可覆寫的 revisions。
- 既有本機資料會保留；請在首次登入前先從 App 匯出 JSON 備份。
- 已登入過的同一裝置可以離線儲存。本機版本與待上傳佇列在同一個 IndexedDB 交易寫入，不必等待雲端回應。
- 網頁載入完成後會快取 App 畫面與靜態資源，可在斷網時重新開啟。首次載入和首次 Google 登入仍需要網絡。
- 恢復已登入資料時不先載入 Google 登入 iframe，避免 Safari 離線重開時等待網絡；按下登入才啟動 Google popup。
- 恢復連線或回到 App 時自動同步；暫時上傳失敗會保留本機紀錄並重試。只有雲端確認成功後才移除待上傳項目。
- 更新 App 時，正在編輯的表單會先保留，儲存或關閉後才可按「更新」。
- Firebase 專案：dicky-ontime-2026。
- 首次使用前，必須在 Firebase Console 啟用 Authentication → Google 登入，並設定授權網域；同時建立 Firestore database 並部署 firestore.rules。

## 部署
```powershell
firebase.cmd deploy --only firestore:rules --project dicky-ontime-2026
git push origin main
```
GitHub Pages 使用根目錄 index.html，不需要 Firebase Hosting。

## 睡眠與補登介面

- 「記錄睡眠」先填入睡、起床與選填備註；睡眠計畫可以另外展開。
- 日期與時間分開選擇。新增睡眠時，起床時間早於入睡時間會帶入隔天；手動修改日期後會保留你的選擇。
- 起床時間可以留空，之後按「現在起床」或修改紀錄補上。
- 只有夏令時間結束、同一時間出現兩次時才顯示選擇；修改備註會保留原本的時間與秒數。
- 「補登／修正紀錄」先選出門、去程搭車、抵達、上班、下班、離開工作地點、回程搭車或到家，一次只填這個環節的日期與時間。只更新選中的時間，其餘紀錄保持原值。
- 依工作與日期尋找當天紀錄；跨午夜會接續未完成的前一日紀錄。同一天有多筆時，必須選擇哪一筆。其他日期、另一趟通勤、班次連結、備註和清除時間可在「更多選項」調整。
- 下班必須有對應的上班紀錄；沒有時可先切換補登上班。
- 日期與時間欄位共用夏令時間處理，補登與睡眠表單的儲存按鈕固定在底部。

## 搭車紀錄

- 首頁進度依序顯示：出門 → 搭車（去程）→ 抵達 → 上班 → 下班 → 搭車（回程）→ 到家。
- 出門後按「搭車了（去程）」；下班後可以直接按「搭車了（回程）」，再記錄到家。
- 沒搭車時可以直接記錄抵達或到家。原本的「離開工作地點」仍可另外記錄，搭車不會替你填入未知的離開時間。
- 補登可分別填寫兩段搭車時間，CSV 與 JSON 備份都會保留。舊紀錄缺少搭車時間時顯示空白，不需要搬移資料。
- 回程搭車後，時間地圖會結束工作地點停留的區間，改為顯示回程；沒記錄離開時間的區間仍會標示時間未知。

## 字體與介面

- 六個主要頁面與共用對話框使用 Inter（英文、數字）和 Noto Sans TC（繁體中文），以 400–600 的字重為主，時間數字使用等寬數字排版。
- 字體放在 `assets/fonts/`，依 Unicode 範圍載入需要的字集，不依賴外部字體服務。兩套字體的 SIL Open Font License 與來源均附在該目錄。
- `assets/app.css` 保存原有版面結構，`assets/design.css` 統一文字層次、卡片、按鈕、表單、手機導覽與深淺色。主色可選晨光金、霧藍與暖琥珀。
- 手機統計摘要使用兩欄，月份圖表保持單列並可水平捲動；睡眠、出勤與通勤表單維持可捲動的對話框。

## 次要表單

- 用餐偏好先選一餐；切換餐別會保留尚未儲存的設定。停用某餐時只收起時間欄位，原偏好仍會保留。
- 工作設定先選一份工作或新增；不計薪、不需通勤時收起相關欄位，原數值仍會保留。通勤與顏色可另外展開。
- 班次與班表範本先填工作和開始／結束時間，班次另外填日期，休息、標題、備註等可另外展開。新增班次不會自動填入午休；修改既有班次會保留未修改的休息、歷史薪資與通勤設定。
- 用餐先選餐別和開始／結束時間，餐點、地點與備註可另外展開。上班、工作地點停留或通勤期間都可記錄用餐；偏好時段只提供建議。用餐不會自動改出勤、休息或扣薪。

## 用餐與工作時間

- 用餐可以和工作或通勤時間重疊；手動新增、修改、確認單一或整批建議都使用相同規則。
- 自動建議優先已安排的休息或工作以外時間，沒有空檔時也可安排班次中的用餐；自動建議仍避開通勤與其他已確認餐次。
- 未記錄休息不會阻止吃飯，也不會因為吃飯自行補入休息。用餐在工作時間內時，時間預算採區間聯集，不重複扣除。
- 結束早於開始及重複餐次仍會提示；超出偏好時段會給文字提示，不要求額外勾選才能儲存。

## 用餐相片

- 「用餐安排 → 手動新增／編輯」在時間下面提供選填的「加入相片」。每餐一張，可預覽、更換或移除，儲存後顯示在餐點卡片；按縮圖可放大查看。
- 時間、餐點、地點與備註和相片一起保存。只改時間或備註會保留相片；移除相片不會刪除餐次。
- 支援瀏覽器可讀取的手機相片、JPG、PNG、WebP 等，原檔上限 20 MB。上傳前在裝置壓縮為最長邊 1280 像素以內的 JPEG，圖片資料上限 256 KiB，方便離線保存與同步。
- 相片存於帳戶的用餐版本內，沿用 IndexedDB 和待同步佇列，不需要公開圖片網址或另外設定 Storage。含相片的用餐版本上限 384 KiB，其他版本仍為 64 KiB；均低於 Firestore 文件大小限制。
- JSON 備份保留相片，支援匯入與其他裝置同步。CSV 只匯出用餐資料，不包含圖片。複製餐次到別天會保留安排資料，相片不會自動複製為另一日的用餐紀錄。

## 按單收入與出勤結算

- 「班表 → 工作設定 → 計薪方式」可選按單收入。外送不用填時薪，新班次與臨時上班都會保留這種計薪方式。
- 「今天」與「統計」的收入紀錄可填整次實收總額（CAD，含小費）與完成訂單數。金額和單數都可留空；空白代表尚未記錄，0 代表實際為 0。
- 編輯收入只更新收入、單數和此筆計薪方式，不修改上班、下班、休息或備註。
- 修改工作設定只影響之後的新紀錄。已有出勤如保留舊時薪，可展開「計薪方式（修正舊紀錄）」改為按單；儲存後停止時薪估算，原時薪值仍保留供修正使用。
- 統計分開顯示時薪估算和手動實收；按單工作不會用工時猜收入。收入依開始上班日期歸屬，跨午夜的工時仍按實際日期分配。出勤 CSV 與 JSON 備份保留計薪方式、收入和單數。
- 斷網保存收入使用原有本機版本與待上傳佇列，恢復連線後自動同步。
- 去程缺少抵達時間時，上班、回程、到家或下一次出門會限制未知區間，不會在到家後繼續增加。統計會標示未知通勤，通勤合計只加已知／預估時間，沒有自行填入抵達時間。

## 介面回歸測試

網站仍然直接使用 `index.html`，不需要建置。測試使用獨立資料庫；同步案例以本機 HTTP 服務替代 Firestore 傳輸，不讀寫正式雲端資料。

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm test
TEST_BROWSER=webkit npm test
```

若使用已安裝的 Chromium，可設定 `CHROMIUM_PATH`。測試涵蓋跨日睡眠、午睡、未結束紀錄、日期驗證、夏令時間、舊紀錄保存、出勤與通勤補登、完整搭車流程與 CSV 匯出，以及 320／390／430 像素手機版和桌面排版。設計檢查包含六頁深淺色、字體載入、班表檢視、月份圖表、主色選擇與文字對比度。

補登測試也涵蓋逐項保存、跨日接續、同日多筆選擇、舊版通勤紀錄，以及休息、收入、備註和其他時間的保留。次要表單驗證三餐切換、隱藏工作設定、班次休息保存、跨日用餐和衝突檢查。

用餐測試涵蓋工作／通勤期間保存、建議確認、休息優先、保留出勤與薪資及避免時間重複扣除。離線測試驗證斷網保存、重新開啟、連線後自動上傳、失敗重試，以及更新時保護未儲存表單。

Linux WebKit 的 Playwright 離線開關會在 Service Worker 之前拒絕導航；該引擎的離線案例改由測試伺服器中斷回應並阻擋外部請求。Chromium 使用瀏覽器實際離線開關。

收入測試涵蓋整次總額、單數、修改與重開、舊時薪修正、未知與零收入、出勤保存、CSV 欄位、新舊計薪快照及離線同步；通勤測試驗證到家後未補抵達的區間不再增加。

相片測試涵蓋加入、預覽、放大、重開、時間修改、更換、移除、大圖片壓縮、錯誤檔案、JSON 備份匯入、離線同步及手機深淺色版面。

### 安裝到手機（PWA）

網站頂部按「安裝 App」。Android Chrome 支援瀏覽器安裝對話框；若未顯示，可從 Chrome 選單選「安裝應用程式／新增至主畫面」。iPhone / iPad 請用 Safari 的「分享 → 加入主畫面 → 加入」。聊天 App 內建瀏覽器請先改用 Safari 或 Chrome。安裝完成後從主畫面開啟；安裝入口在獨立 App 模式隱藏。

首次連網開啟會快取公開網頁、安裝腳本、圖示及字體；之後支援離線啟動與本機儲存，已登入帳號恢復網絡後自動同步。iOS 的安裝版可能使用獨立儲存空間；若看不到原紀錄，請登入同一帳號同步。網頁 manifest 使用相對路徑，安裝範圍只限此 App（GitHub Pages 的 `/codex/`）。
